# M4 Handoff Implementation Plan

> Execution: inline, using executing-plans and test-driven-development.

**Goal:** Hand over the exact fresh-four-model experiment requested by Lee Daegyeong.

**Architecture:** An independent `m4_whisper` package accepts a shared audio window,
loads one of four CT2 artifacts, and preserves the existing guard. ONNX encoder
and decoder graphs are separate interoperability artifacts, not CT2 replacements.
No existing service, model, training code, or microphone defaults are changed.

**Approved scope:** CT2 runtime plus ONNX exports; separate branch and artifact
uploads; base-to-current documentation, explicit I/O and caveats.

## Tasks

- [x] Runtime: write failing tests in `tests/test_m4_handoff.py` for input validation,
  fixed settings, output/error semantics, timestamp offsets, and guard behavior.
  Implement `m4_whisper/runtime.py`, `settings.py`, and `__main__.py` and rerun tests.
  Vendor the existing guard unchanged with its source hash.
- [x] Export: test `m4_whisper/export_onnx.py` on a tiny local randomly initialized
  Whisper, including dynamic decoder lengths and ORT/PyTorch numerical parity.
  Export the baseline and exact fresh merged checkpoint, CPU FP32, no training.
- [x] Artifacts: build only allowlisted model archives; include file hashes, source
  provenance, tokenizer/processor files and license notices. No audio, manifests
  with personal paths, access tokens, or training checkpoints are uploaded.
- [x] Verification: run CT2 baseline/current smoke on local audio, ONNX graph and
  numerical checks, related unit tests; record commands and limitations separately
  from the historical 2,398-file recognition benchmark.
- [ ] Delivery: write `m4_whisper/README.md` in Korean, explain input/output and
  metric definitions, publish prerelease assets, push only this feature branch.
  Do not merge or change production defaults.

## Fixed Values

CT2 CPU; faster-whisper 1.2.1; CTranslate2 4.8.1; worker 1; six CPU threads;
selection_regenerate; first n=0; regeneration n=3, temperature=0, beam=5;
repetition_penalty=1; at most one regeneration per suspicious segment.
The guard's 224-token eligibility heuristic is not the CT2 448-token context limit.
